# 0011 — Text

- **Status:** draft
- **Depends on:** 0010

## Goal

A Midnight program can draw shapes, and nothing else: a score is a row of
rectangles, and "GAME OVER" is out of reach. After this spec a system
draws text:

```ruby
resource Score
  points: Int
  missed: Int
end

system show
  points = Score.points.to_s.rjust(5, "0")
  Draw.text(8, 8, "SCORE #{points}", 24, Color(255, 255, 255))
  if Score.missed >= 3
    message = "GAME OVER"
    Draw.text((Window.width - message.length * 12) / 2, 88, message, 24, Color(255, 80, 80))
  end
end

Window.background = Color(16, 16, 32)
Window.open("Catch", 320, 200)
World.run
```

`Draw.text(x, y, text, size, color)` is a fifth statement under `Draw`.
It draws `text` with one font built into Midnight, monogram, whose
characters all take a cell of the same size: a cell is `size / 2` points
wide and `size` points high, so a line of `n` characters is
`n * size / 2` points wide, and centering is arithmetic. `x` and `y` are
the top left corner of the first cell. `"\n"` starts a new line. A
character the font does not have draws a replacement glyph, a hollow box,
in its cell.

Which pixels a character covers is decided as for the shapes: each
pixel of the font is a small rectangle, and a pixel of the frame is
covered when its center is inside a set one. So text is the same bytes
on every device, and `draws` lists it as the statement that drew it:

```
midnight: drive:   Draw.text(8.0, 8.0, "SCORE 00040", 24.0, Color(255, 255, 255, 255))
```

### How this serves the principles

- **Agents write, people review.** Text is drawn where the source says,
  with all it needs in its arguments: no font to load, no size or color
  set beforehand, no anchor to choose. Position first and color last is
  the order of the four shapes, so there is one order to learn.
- **The domain is in the language.** The compiler knows a draw of text:
  it says when one stands in a GPU system, why a loop that draws text
  runs on one core, and what to write when a toolkit's name for the call
  is used.
- **Fast by construction.** A draw of text costs a record and the bytes
  of its string in a frame's list; the device tests the pixels of each
  character's cell, as for a small rectangle.
- **Observable and repeatable.** `draws` lists text as text, with no
  device, so an agent checks a score without looking at a picture; the
  pixels of text are a definition in the reference, the same on every
  device. A rule that the widths of characters are equal keeps the size
  of any text arithmetic.
- **Errors teach.** A string given first, a size left out, a number given
  as the text and the names other toolkits use are each recognized, and
  the message says what to write.
- **Grown by building things in it.** A score and a "GAME OVER" are the
  first thing every small game needs that Midnight lacks.

## Scope

- The statement `Draw.text`, its arguments, where it may stand, and what
  it adds to a frame.
- The built-in font: monogram's printable ASCII and Latin-1 characters,
  and a replacement glyph; one file in the repository that the runtime
  and the reference renderer both take it from.
- Which pixels text covers, at every scale.
- Text in `draws` and its JSON form.
- `ljust` and `rjust` with a padding string, for numbers padded with
  zeros.
- An example game with a score.
- The reference becomes Midnight 0.10 and the compiler 0.10.0.

## Non-goals

- Fonts other than the built-in one, fonts as values, and text whose
  characters differ in width. A later spec that adds them keeps what
  `Draw.text(x, y, text, size, color)` means.
- A call that measures text, alignment, wrapping, rotation, outlines and
  shadows. Centering is arithmetic; an outline is the same text drawn
  again, offset.
- Characters outside the font, combining marks, right-to-left text and
  shaping: every character is one cell, left to right.
- Text in a GPU system. A GPU system has no strings.
- Smoothed edges. A pixel is covered or it is not.
- Text input: typing into a program.
- Text in `midnight plan`.

## Design

### The statement

```ruby
Draw.text(x, y, text, size, color)
```

| Argument | Type | Meaning |
| -------- | ---- | ------- |
| `x`, `y` | `Float` | The top left corner of the first character's cell, in points. |
| `text`   | `String` | What is drawn. |
| `size`   | `Float` | The height of a line, in points. A cell is `size / 2` points wide. |
| `color`  | `Color` | The color of the characters. Nothing is drawn behind them. |

- It follows every rule of the four shapes: a statement with no value,
  every argument given by position, an `Int` converting to `Float`,
  allowed wherever a statement can stand but in a GPU system, its
  numbers kept as 32-bit `Float`s, and a draw while no window is open
  dropped after its arguments are evaluated. Its arguments are evaluated
  in the order written.
- `size` is the height of a line, from the top of one line to the top of
  the next; the space between lines is part of it. It is not a "font
  size" in the sense of other toolkits.
- A `size` that is not greater than zero draws nothing, and so does a
  draw with a NaN among its numbers. Neither is an error. An empty string
  draws nothing.

**Lines and cells.** The text is read as Unicode characters (code
points), left to right. `"\n"` ends a line: the next character's cell is
at `x` again, `size` points lower. Every other character takes one cell,
the next to the right. So a line of `n` characters, `"\n"` not counted,
covers the rectangle from `x`, `y` that is `n * size / 2` points wide
and `size` points high, and the `i`th line, counting from 0, begins at
`y + i * size`.

```ruby
title = "MIDNIGHT"
Draw.text((Window.width - title.length * 24) / 2, 40, title, 48, Color(255, 255, 255))
```

**What a cell shows.**

- A character of the font shows its glyph. The font has the printable
  characters of ASCII (`" "` to `"~"`) and of Latin-1 (U+00A0 to
  U+00FF): letters with accents, `£`, `°`, `±`, `×` and the rest.
- A space and U+00A0 show nothing.
- Every other character shows the **replacement glyph**, a hollow box
  the height of a capital letter: control characters such as `"\t"`,
  `"\r"` and `"\e"` included. A character the font lacks is never an
  error and never moves the characters after it.

**Even pixels.** A pixel of the font is `size / 12` points square. On a
window whose scale is `s`, it covers `size / 12 * s` pixels of the
frame, and the font's pixels are all the same size only when that is a
whole number. Text at a `size` that is a multiple of 24 looks even at
scales of 1, 1.5 and 2; at a multiple of 12, at scales of 1 and 2.
Other sizes are drawn by the same rule and are as exact, but some of the
font's rows and columns are a pixel wider than others.

### The font

The font is **monogram** by Vinícius Menézio
(<https://datagoblin.itch.io/monogram>), released under CC0 1.0: it can
be used, changed and shipped by anyone, in any program, with no notice.
A cell is 6 pixels of the font wide and 12 high: a glyph is 5 pixels
wide with an empty column on its right, capital letters stand in rows 3
to 9 counted from 0 at the top, and descenders reach row 11.

`runtime/font.txt` holds it, as text:

- a header of lines that begin with `#`: the source, the SHA-256 of the
  file it was taken from, the license, and the credit;
- for each glyph a line `U+XXXX`, then 12 lines of 6 characters, `#` for
  a set pixel of the font and `.` for a clear one; glyphs in order of
  their code point;
- the replacement glyph, under the line `replacement`.

It holds the 95 printable ASCII characters, the 94 printable Latin-1
characters monogram has, a blank glyph for U+00A0, and the replacement
glyph, which Midnight adds: 191 glyphs. It is taken from
`monogram-bitmap.json` in `monogram.zip` (SHA-256
`81d0540290f73d6317dc86e34978af80babf8e24129941cdf087b0fdfb75c287`),
whose own SHA-256 is
`847e18d10ecd0fd4362ee0088a1bc56f9b203136b544d45db17426ff91913938`;
glyphs are not changed. U+00AD, a soft hyphen, which monogram does not
have, shows the replacement glyph.

The file is part of the reference: "Text" names it as the definition of
every glyph, and the reference's tables show none. The compiler includes
it, and writes the glyphs as a table of the generated window code of a
program that draws text; the reference renderer reads it. Nothing else
holds the glyphs.

### Which pixels text covers

This extends "Which pixels a shape covers" and uses its pixel centers
and its 32-bit steps.

```
u = size / 12
```

is one 32-bit division. For the line `i` of the text, counting from 0,
and the cell `k` of that line, the font's pixel in column `j` (0 to 5)
and row `r` (0 to 11) of the cell's glyph covers the rectangle

```
from x + c * u        to x + (c + 1) * u,     c = 6 * k + j
from y + R * u        to y + (R + 1) * u,     R = 12 * i + r
```

each bound computed as the product of the whole number (`c`, `c + 1`,
`R` or `R + 1`, converted to a 32-bit `Float`) and `u`, rounded, then
the sum, rounded. A pixel of the frame is covered when its center is in
a rectangle of a set pixel of a glyph, by the rectangle test:
`left <= px < right` and `top <= py < bottom`.

- Every bound is computed from the start of the text, not from the
  cell: two pixels of the font side by side, in one glyph or in two,
  share the bound between them, so text has no gap and no overlap
  between its characters or its lines, whatever the numbers.
- The whole numbers are exact as 32-bit `Float`s below 16,777,216: up to
  2,796,202 characters a line and 1,398,101 lines.
- At a scale of 1, `Draw.text(10, 20, "A", 12, c)` is the glyph of `A`
  with each pixel of the font on one pixel of the frame, its top left at
  column 10 and row 20.

**Determinism.** "Determinism of a frame" applies to text as written for
the shapes: the list of draws is exact; a device may differ from the
rule only at a pixel for which the two sides of a test are equal or one
32-bit step apart, and for a draw with a number that is infinite, below
about 1.18e-38 in magnitude and not zero, or whose test overflows; a
color with an `a` of 255 gives its bytes exactly. A draw of text is one
draw for the allowance on translucent colors: no two of its font pixels
cover one pixel of the frame.

### Where text may be drawn

- **GPU systems.** `Draw.text` in a GPU block, or in a function a GPU
  system calls, is a compile error at the statement:

  ```
  error: `Draw.text` can't stand in a GPU system
    --> stars.12am:14:5
     |
  14 |     Draw.text(star.x, star.y, "*", 12, Color(255, 255, 0))
     |     ^^^^^^^^^ draw text from an ordinary system: a GPU system has no strings
  ```

  In a function a GPU system calls, the note names the system and the
  call, as the other errors of GPU systems do. This error is reported in
  place of the error for a `String` value in a GPU system, and of the
  error for a draw in a loop inside a GPU block.
- **Several cores.** Every expression of type `String` keeps an `each`
  on one core (rule 1 of "Independent loops"), so an `each` that draws
  text runs on one core, and `midnight loops` gives the reason it gives
  for any string: `` uses a `String` at line N ``. "Draws on several
  cores" says so, and that a label drawn for each entity of a component a
  GPU system keeps in GPU memory brings its array back in every tick, as
  any ordinary system that reads it does.

### Diagnostics

Each is one line, its hint in the label:

- a `String` as the first argument:
  `` `Draw.text` takes its text third ``, label
  `` write `Draw.text(x, y, text, size, color)` ``;
- four arguments whose last is a `Color`:
  `` `Draw.text` needs a size ``, label
  `` write `Draw.text(x, y, text, size, color)`: the size is the height of a line in points ``;
- a third argument that is not a `String`:
  `` `Draw.text` takes a `String` to draw ``, label
  `` write `"#{…}"` to draw a value ``, with the argument's source in
  place of `…` when it is a name or a field;
- any other count or type of arguments, and an argument given by name:
  as for the shapes, the label giving `` `Draw.text(x, y, text, size, color)` ``;
- the names other toolkits use: `Draw.print`, `Draw.puts`,
  `Draw.string`, `Draw.label`, `Draw.write` and `Draw.fill_text`, an
  unknown function named `text`, `draw_text`, `print_text` or
  `fill_text`, and an unknown type `Text` or `Label` that is constructed
  or spawned:

  ```
  error: `Draw` has no `print`
     |        ^^^^^ write `Draw.text(x, y, text, size, color)`
  ```

- `Draw.sprite` and `Draw.image`:
  `` `Draw.sprite` is not in this version of Midnight, which draws shapes and text ``;
- `Draw.text` in a GPU system, above.

A program that draws text and has no `Window.open` gets the error every
draw gets.

### `ljust` and `rjust` with a padding string

`s.ljust(n, pad)` and `s.rjust(n, pad)` pad with `pad`, repeated and cut
as needed, instead of spaces, as Ruby's do: `"42".rjust(5, "0")` is
`"00042"` and `"ab".ljust(7, "xy")` is `"abxyxyx"`. `n` counts
characters. An empty `pad` is a run-time error,
`` `rjust` needs a padding string that is not empty ``. The forms with
one argument are unchanged.

### `draws` and JSON

A draw of text is listed as the statement that made it, the string
written as `to_s` writes a `String` inside a struct: quoted, with
Midnight's escapes.

```
midnight: drive:   Draw.text(8.0, 8.0, "SCORE 00040\nLIVES 3", 24.0, Color(255, 255, 255, 255))
```

In JSON a shape is `{"shape":"text","x":…,"y":…,"text":"…","size":…,"color":[…]}`,
the string with the escapes of `docs/json.md`. A string of any length
is printed whole.

### The compiler

- The typed program gains a fifth shape, `Text`. A draw's arguments are
  held in source order with their types (`args`, in place of the numbers
  and the color), so the emitter evaluates them in the order written.
  This changes `src/tir.rs`, a contract.
- The checker matches `Draw.text(` as it matches the shapes, and gives
  the diagnostics above. The GPU checker gives the text error before the
  error for a `String` and the error for a draw in a loop.
- The effect analysis needs no change: the `String` argument keeps the
  loop on one core.
- The emitter calls `mn_draw_text(x, y, text, size, color)`. In a
  program that draws text, the window code it writes gains the font's
  table, made from `runtime/font.txt`; a program that draws no text is
  built as in 0.9.
- `ljust` and `rjust` take an optional second argument, a `String`.

### The runtime

- **The record.** A draw of text is one record of 32 bytes, of kind
  `MN_DRAW_TEXT`, holding `x`, `y` and `size` as 32-bit `Float`s and,
  as 32-bit whole numbers, the offset and length of its string's bytes
  in a byte array that belongs to the list of draws. The bytes are
  copied when the statement runs; the record holds no pointer and the
  list holds no counted buffer. The array is cleared, swapped and freed
  with the records. A frame's text beyond 4 GiB stops the program with
  the out-of-memory error.
- `mn_draw_text` is never called in a piece: "Several threads" in
  `midnight_rt.h` says so at the function, and a debug build checks it.
- **Rendering.** When a frame is rendered, each record of text in a span
  is replaced by one record for each character that shows a glyph (not
  a space, U+00A0 or `"\n"`): the text's `x` and `y`, `u`, the glyph's
  index, the cell's first column `6 * k` and first row `12 * i`, and the
  color. A span is still one upload, so what `MIDNIGHT_GPU=stats` counts
  does not change. These records are private to `midnight_window.c`.
- **The shader.** The glyphs are a second binding of the shape
  pipeline, a uniform array written once when the pipeline is made. A
  glyph's quad is its cell's rectangle, made one pixel larger and
  clamped, as for the shapes. The fragment stage finds the column and row
  of the font's pixel that holds the center: it may estimate them with a
  division, and then moves to the neighbor while a bound's test says so,
  every bound computed as above, every product through the xor barrier.
  The tests alone decide.
- `midnight_rt.c` keeps the list and never renders; it has no font.

### What a draw of text costs

- A draw of text in ordinary code appends 32 bytes and the bytes of its
  string to the frame's list.
- When a shown frame is rendered, the CPU writes 32 bytes for each
  character that shows a glyph, and the device tests every pixel of each
  such character's cell.
- `bench/draws.sh` gains text, and "What a draw costs" its numbers on
  the RTX 5090, the integrated Radeon and `llvmpipe`: lines of 40
  characters at 24 points, up to 100,000 characters a frame.

### The example

`examples/catch.12am`: a basket moved with the arrow keys catches
falling stars; the score is drawn at the top left, padded with zeros,
and after three missed stars "GAME OVER" is drawn centered, with the
score under it. It draws text and shapes, reads the keyboard, and runs
headless with its `.drive`, `.draws` and `.out`.

## Decisions

- **The font is monogram.** It is CC0 by its author's statement on its
  page and in its files, an original design, made for games, with
  lowercase letters and descenders, and its strokes read well at the
  sizes games use. Any program can contain it with no notice.
- **One font, whose characters are all one width.** The size of text is
  then arithmetic on `length`, digits that change do not move, and no
  call to measure is needed.
- **A statement under `Draw`, named `text`.** It is the word most
  toolkits use, and it sits beside the shapes as a noun.
- **Position first, color last.** The shapes' order, so there is one
  order; a string where a number belongs is a type error the compiler
  explains.
- **The top left corner, and `size` the height of a line.** Every
  toolkit with a built-in bitmap font anchors at the top left, and a
  height in points is a length like every other argument of `Draw`. A
  font added later keeps both meanings.
- **`"\n"` starts a line; anything else is one cell.** A newline is the
  commonest thing other toolkits fail to handle; with one rule for the
  rest, the width of a line is its count of characters.
- **A visible replacement glyph.** A character that shows nothing, or a
  `?`, hides a mistake; one that moves the text after it breaks the
  arithmetic.
- **Pixels of the font are rectangles under 0009's rule.** Text is then
  exact on every device by the same definition and the same tests as
  the shapes, on one grid for the whole text.
- **Not in GPU systems, and on one core.** Both follow from what strings
  already are, so nothing new is needed for either.
- **The bytes are copied into the frame.** The list holds no counted
  buffer and no pointer, so it stays plain bytes that pieces, the device
  and debug builds already handle.
- **`ljust` and `rjust` take a padding string.** Scores are padded with
  zeros; Ruby's methods do it with the meaning they have there.

## Measured in planning

From the planning probe on the RTX 5090, RADV and `llvmpipe`, over
10,080 pictures a variant and device: targets of 256 by 256 and 250 by
200 pixels at scales 1, 1.25, 1.5 and 2; cells of 8 by 8, 8 by 16, 8 by
12, 6 by 7 and random fonts; positions on whole points, halves and
anywhere; sizes multiples of the cell's height and anywhere.

- The rule as written, with the barrier and the correction, gave every
  opaque picture byte for byte as the rule computed on the CPU, on all
  three devices, with the font in a storage buffer, a texture or a
  uniform, one instance a glyph or one a line; counters of every covered
  pixel agreed in the translucent pictures too. A binary search over the
  bounds in place of the estimate gave the same pictures.
- Without the barrier, the 5090 and RADV fused `x + c * u` and differed
  from the rule in 7 of 10,080 pictures; `llvmpipe` did not fuse.
- Without the correction, the estimate alone was wrong in 13 opaque
  pictures of 5,040 on the 5090, 14 on `llvmpipe` and 437 on RADV
  (660,591 pixels), never by more than one column or row. RADV's
  division goes wrong exactly where the quotient is a whole number:
  text at whole or half points at a size that is a multiple of the
  cell's height, the commonest case.
- Translucent text kept 0009's allowance: the 5090 equal to the rule,
  RADV within 2 and `llvmpipe` within 3, never more than one per
  translucent draw over a pixel.
- On the CPU: computing a bound with a fused multiply-add instead of a
  product and a sum changed 31 covered pixels of 370 million; a glyph
  placed from its own rounded origin instead of the text's changed 49;
  `floor((px - x) / u)`, correctly rounded, chose the wrong column or
  row at 1,301 pixels and never by more than one. Hence the barrier, the
  bounds from the start of the text, and the correction after the
  estimate.
- With a cell 12 high, `u` is exact for whole sizes that are multiples
  of 3, and the end of a line computed from `length` meets the text's
  last bound exactly for every multiple of 12 and for 98% of lines and
  sizes otherwise; with a cell 8 or 16 high it always does.
