# 0011 — Text

- **Status:** implemented
- **Depends on:** 0010

## Goal

A Midnight program can draw shapes, and nothing else: a score is a row of
rectangles, and "GAME OVER" is out of reach. After this spec a system
draws text:

```ruby
resource Score
  points: Int = 0
  missed: Int = 0
end

system show
  points = Score.points.to_s.rjust(5, "0")
  Draw.text(8, 8, "SCORE #{points}", 24, Color(255, 255, 255))
  if Score.missed >= 3
    message = "GAME OVER"
    Draw.text((Window.width - message.length * 12) / 2, 88, message, 24, Color(255, 80, 80))
  end
end

Window.background = Color(16, 16, 32)
Window.open("Catch", 320, 200)
World.run
```

`Draw.text(x, y, text, size, color)` is a fifth statement under `Draw`.
It draws `text` with one font built into Midnight, monogram, whose
characters all take a cell of the same size: at the sizes the reference
recommends a cell is `size / 2` points wide and `size` points high, so a
line of `n` characters is `n * size / 2` points wide, and centering is
arithmetic. `x` and `y` are the top left corner of the first cell.
`"\n"` starts a new line. A character the font does not have draws a
replacement glyph, a hollow box, in its cell.

Which pixels a character covers is decided as for the shapes: each
pixel of the font is a small rectangle, and a pixel of the frame is
covered when its center is inside a set one. So which pixels text covers
is a rule in the reference, measured byte for byte the same on the
devices tested, and `draws` lists text as the statement that drew it:

```
midnight: drive:   Draw.text(8.0, 8.0, "SCORE 00040", 24.0, Color(255, 255, 255, 255))
```

### How this serves the principles

- **Agents write, people review.** Text is drawn where the source says,
  with all it needs in its arguments: no font to load, no size or color
  set beforehand, no anchor to choose. Position first and color last is
  the order of the four shapes, so there is one order to learn.
- **The domain is in the language.** The compiler knows a draw of text:
  it says when one stands in a GPU system, why a loop that draws text
  runs on one core, and what to write when a toolkit's name for the call
  is used.
- **Fast by construction.** A draw of text costs a record and the bytes
  of its string in a frame's list; the device tests the pixels of each
  character's cell, as for a small rectangle.
- **Observable and repeatable.** `draws` lists text as text, with no
  device, so an agent checks a score without looking at a picture; the
  pixels of text are a definition in the reference, which the tests hold
  every device to. Characters of one width keep the size of any text
  arithmetic.
- **Errors teach.** A string given first, a size left out, a number given
  as the text and the names other toolkits use are each recognized, and
  the message says what to write.
- **Grown by building things in it.** A score and a "GAME OVER" are the
  first thing every small game needs that Midnight lacks.

## Scope

- The statement `Draw.text`, its arguments, where it may stand, and what
  it adds to a frame.
- The built-in font: monogram's printable ASCII and Latin-1 characters,
  and a replacement glyph; one file in the repository,
  `runtime/font.txt`, from which the compiler and the reference renderer
  both take it.
- Which pixels text covers, at every scale.
- Text in `draws` and its JSON form.
- `ljust` and `rjust` with a padding string, for numbers padded with
  zeros.
- An example game with a score.
- The reference becomes Midnight 0.10 and the compiler 0.10.0.

## Non-goals

- Fonts other than the built-in one, fonts as values, and text whose
  characters differ in width. A later spec that adds them keeps what
  `Draw.text(x, y, text, size, color)` means.
- A call that measures text, alignment, wrapping, rotation, outlines and
  shadows. Centering is arithmetic; an outline is the same text drawn
  again, offset.
- Characters outside the font, combining marks, right-to-left text and
  shaping: every character is one cell, left to right.
- Text in a GPU system. A GPU system has no strings.
- Smoothed edges. A pixel is covered or it is not.
- Text input: typing into a program.
- Text in `midnight plan`.

## Design

### The statement

```ruby
Draw.text(x, y, text, size, color)
```

| Argument | Type | Meaning |
| -------- | ---- | ------- |
| `x`, `y` | `Float` | The top left corner of the first character's cell, in points. |
| `text`   | `String` | What is drawn. |
| `size`   | `Float` | The height of a line, in points. |
| `color`  | `Color` | The color of the characters. Nothing is drawn behind them. |

- It follows every rule of the four shapes: a statement with no value,
  every argument given by position, an `Int` converting to `Float`,
  allowed wherever a statement can stand but in a GPU system, its
  numbers kept as 32-bit `Float`s, and a draw while no window is open
  dropped after its arguments are evaluated. Its arguments are evaluated
  in the order written.
- `size` is the height of a line, from the top of one line to the top of
  the next; the space between lines is part of it. It is not a "font
  size" in the sense of other toolkits.
- A `size` that is not greater than zero draws nothing, and so does a
  draw with a NaN among its numbers. Neither is an error. An empty string
  draws nothing.

**Lines and cells.** The text is read as Unicode characters (code
points), left to right. `"\n"` ends a line: the next character's cell is
at `x` again, one line lower. Every other character takes one cell, the
next to the right. A pixel of the font is `u = size / 12` points square
(below), a cell is 6 of them wide and 12 high, and a line is 12 high:

- a line of `n` characters, `"\n"` not counted, lies within the
  rectangle from `x`, `y` to `x + (6 * n) * u`, `y + 12 * u`;
- the line `i`, counting from 0, begins at `y + (12 * i) * u`.

When `size` is a whole multiple of 3, `u` is exact, and these are
`n * size / 2` points wide, `size` high, and `y + i * size`: what a
program computes from `length`. The reference recommends a `size` of 24
or a multiple of it, which also keeps the font's pixels even (below),
and the examples use them:

```ruby
title = "MIDNIGHT"
Draw.text((Window.width - title.length * 24) / 2, 40, title, 48, Color(255, 255, 255))
```

**What a cell shows.**

- A character of the font shows its glyph. The font has the 95
  printable characters of ASCII (`" "` to `"~"`) and the characters
  U+00A0 to U+00FF but U+00AD: letters with accents, `£`, `°`, `±`, `×`
  and the rest.
- A space and U+00A0 show nothing.
- Every other character shows the **replacement glyph**, a hollow box:
  U+00AD, control characters such as `"\t"`, `"\r"` and `"\e"`, and
  every character beyond U+00FF. So `"\r\n"` ends a line with the
  replacement glyph in the cell before the break. A character the font
  lacks is never an error and never moves the characters after it.

**Even pixels.** On a window whose scale is `s`, a pixel of the font
covers `size / 12 * s` pixels of the frame, and the font's pixels are
all the same size only when that is a whole number. Text at a `size`
that is a multiple of 24 looks even at scales of 1, 1.5 and 2, and a
multiple of 48 at 1.25 as well; a multiple of 12, at scales of 1 and 2.
Other sizes are drawn by the same rule and are as exact, but some of the
font's rows and columns are a pixel wider than others.

### The font

The font is **monogram** by Vinícius Menézio
(<https://datagoblin.itch.io/monogram>), released under CC0 1.0: it can
be used, changed and shipped by anyone, in any program, with no notice.
A cell is 6 pixels of the font wide and 12 high. Capital letters stand
in rows 3 to 9 counted from 0 at the top, accents over capitals reach
row 0, and descenders reach row 11. Glyphs are 5 pixels wide with column
5 clear, but for `ð` (U+00F0), whose stroke reaches column 5 in row 3;
it is kept as monogram draws it.

`runtime/font.txt` holds it, as text:

- a header of lines that begin with `# ` (a `#` and a space), before the
  first glyph: the source, the SHA-256 of the files it was taken from,
  the license, and the credit;
- for each glyph a line `U+XXXX`, four upper-case hexadecimal digits,
  then 12 lines of exactly 6 characters, `#` for a set pixel of the font
  and `.` for a clear one, every column read; glyphs in order of their
  code point;
- the replacement glyph, under the line `replacement`, last.

Nothing else is in the file, and it ends with a newline. It holds 191
glyphs: U+0020 to U+007E, U+00A0 to U+00FF but U+00AD, and the
replacement. They are taken from `monogram-bitmap.json` in
`monogram.zip` (SHA-256
`81d0540290f73d6317dc86e34978af80babf8e24129941cdf087b0fdfb75c287`),
whose own SHA-256 is
`847e18d10ecd0fd4362ee0088a1bc56f9b203136b544d45db17426ff91913938`,
unchanged; monogram has no glyph for U+00A0, and the file's is blank.
The replacement glyph, which Midnight adds, is the outline of the
capital letters' box, rows 3 to 9 and columns 0 to 4, one pixel thick:

```
replacement
......
......
......
#####.
#...#.
#...#.
#...#.
#...#.
#...#.
#####.
......
......
```

The file is part of the definition of the language: the reference's
"Text" names it as the definition of every glyph and shows none, and the
repository's `CLAUDE.md` lists it under "What defines what". The
compiler includes it, and the glyphs reach the device as "The runtime"
says; the reference renderer reads it. Nothing else holds the glyphs.

### Which pixels text covers

This extends "Which pixels a shape covers" and uses its pixel centers
and its 32-bit steps.

```
u = size / 12
```

is one 32-bit division, made on the CPU. For the line `i` of the text,
counting from 0, and the cell `k` of that line, the font's pixel in
column `j` (0 to 5) and row `r` (0 to 11) of the cell's glyph covers the
rectangle

```
from x + c * u        to x + (c + 1) * u,     c = 6 * k + j
from y + R * u        to y + (R + 1) * u,     R = 12 * i + r
```

each bound computed as the product of the whole number (`c`, `c + 1`,
`R` or `R + 1`, converted to the nearest 32-bit `Float`) and `u`,
rounded, then the sum, rounded. A pixel of the frame is covered when its
center is in a rectangle of a set pixel of a glyph, by the rectangle
test: `left <= px < right` and `top <= py < bottom`.

- Every bound is computed from the start of the text, not from the
  cell: two pixels of the font side by side, in one glyph or in two,
  share the bound between them, so text has no gap and no overlap
  between its characters or its lines, whatever the numbers.
- The whole numbers are exact as 32-bit `Float`s below 16,777,216: up to
  2,796,202 characters a line and 1,398,101 lines.
- At a scale of 1, `Draw.text(10, 20, "A", 12, c)` puts each pixel of
  the font on one pixel of the frame: the cell covers columns 10 to 15
  and rows 20 to 31, and the letter's pixels lie in columns 10 to 14 and
  rows 23 to 29.

**Determinism.** "Determinism of a frame" applies to text as written for
the shapes: the list of draws is exact; a device may differ from the
rule only at a pixel for which the two sides of a test are equal or one
32-bit step apart, and for a draw with a number that is infinite, or
below about 1.18e-38 in magnitude and not zero, a draw of text whose
`size` is below about 1.41e-37 and not zero (its `u` is then below
1.18e-38), a draw of text with a line of more than 2,796,202 characters
or more than 1,398,101 lines, or a draw whose test overflows; a color
with an `a` of 255 gives its bytes exactly. A draw of text is one draw
for the allowance on translucent colors: no two of its font pixels cover
one pixel of the frame.

### Where text may be drawn

- **GPU systems.** `Draw.text` in a GPU block, anywhere in it, or in a
  function a GPU system calls, is one compile error at the statement's
  `Draw.text`: `` `Draw.text` can't stand in a GPU system `` in a GPU
  block, and `` `Draw.text` can't stand in a function called from a GPU
  system `` in a function, with the note that names the system and the
  call. Its label is
  `draw text from an ordinary system: a GPU system has no strings`.

  ```
  error: `Draw.text` can't stand in a GPU system
    --> stars.12am:14:5
     |
  14 |     Draw.text(star.x, star.y, "*", 12, Color(255, 255, 0))
     |     ^^^^^^^^^ draw text from an ordinary system: a GPU system has no strings
  ```

  It is reported in place of every other error the statement itself
  would get in GPU code: a `String` value, and a draw in a loop, in the
  nested `each` or in a function. The text argument is part of the
  report and is not checked further; `x`, `y`, `size` and `color` are
  checked by the rules of GPU code as for any draw.
- **Several cores.** Every expression of type `String` keeps an `each`
  on one core (rule 1 of "Independent loops"), so an `each` that draws
  text runs on one core, and `midnight loops` gives the reason it gives
  for any string: `` uses a `String` at line N ``. "Draws on several
  cores" says so, and that a label drawn for each entity of a component a
  GPU system keeps in GPU memory brings its array back in every tick, as
  any ordinary system that reads it does.

### Diagnostics

Each is one line, its hint in the label. For the arguments, in this
order, the first that applies is the statement's one error about the
form of its arguments:

1. an argument given by name: as for the shapes, its label
   `` its arguments go by position: `Draw.text(x, y, text, size, color)` ``;
2. a `Color` as the first argument: as for the shapes,
   `` `Draw.text` takes its color last ``;
3. a `String` as the first or the second argument, whatever the count:
   `` `Draw.text` takes its text third ``, label
   `` write `Draw.text(x, y, text, size, color)` ``;
4. four arguments, the third a `String` and the fourth a `Color`:
   `` `Draw.text` needs a size ``, label
   `` write `Draw.text(x, y, text, size, color)`: the size is the height of a line in points ``;
5. any other count: as for the shapes,
   `` `Draw.text` takes 5 arguments, but N were given ``, label
   `` `Draw.text(x, y, text, size, color)` ``.

With five arguments given by position, each that does not have its type
is reported, in the same pass:

- a third argument that is not a `String`:
  `` `Draw.text` takes a `String` to draw ``, label
  ``write `"#{NAME}"` to draw a value``, with the argument's source as
  `NAME` when it is a variable, a constant or a field read (`score`,
  `MAX`, `Score.points`, `ball.hp`), and ``write `"#{…}"` to draw a
  value`` with `…` as written otherwise;
- any other argument, as for the shapes.

The names other toolkits use:

- `Draw.print`, `Draw.puts`, `Draw.string`, `Draw.label`, `Draw.write`
  and `Draw.fill_text`:

  ```
  error: `Draw` has no `print`
    --> score.12am:9:8
     |
   9 |   Draw.print("SCORE", 8, 8)
     |        ^^^^^ write `Draw.text(x, y, text, size, color)`
  ```

- a function named `text`, `draw_text`, `print_text` or `fill_text`,
  and a type `Text` or `Label` that is constructed or spawned, when the
  program declares none by that name: the usual
  ``unknown function `draw_text` ``, ``unknown type `Text` `` or
  ``unknown component `Label` ``, with the label
  `` text is drawn with `Draw.text(x, y, text, size, color)` ``.

`Draw.sprite` and `Draw.image`:
`` `Draw.NAME` is not in this version of Midnight, which draws shapes and text ``,
with the name written.

A program that draws text and has no `Window.open` gets the error every
draw gets.

### `ljust` and `rjust` with a padding string

`s.ljust(n, pad)` and `s.rjust(n, pad)` pad with `pad`, repeated and cut
after a whole character as needed, in place of spaces, as Ruby's do:
`"42".rjust(5, "0")` is `"00042"` and `"ab".ljust(7, "xy")` is
`"abxyxyx"`. `n` counts characters. An empty `pad` is a run-time error
whatever `n` is: `` `ljust` needs a padding string that is not empty ``,
or the same with `rjust`. The forms with one argument are unchanged.

### `draws` and JSON

A draw of text is listed as the statement that made it, the string
written as `to_s` writes a `String` inside a struct: quoted; `\n`, `\t`,
`\r`, `\0`, `\e`, `\\` and `\"` escaped; `\#` before `{`; every other
byte below 0x20 as `\x` and two upper-case hexadecimal digits; and
everything else as itself.

```
midnight: drive:   Draw.text(8.0, 8.0, "SCORE 00040\nLIVES 3", 24.0, Color(255, 255, 255, 255))
```

In JSON a shape is `{"shape":"text","x":…,"y":…,"text":"…","size":…,"color":[…]}`,
the string with the escapes of `docs/json.md`. A string of any length
is printed whole. The `format` stays 1: a new value of `shape` is a
change "Stability" in `docs/json.md` allows. Its "A shape is an object"
paragraph becomes: "A shape is an object with `shape` (`rect`, `circle`,
`line`, `triangle` or `text`) and its arguments in order under the
names of the reference's table (`x`, `y`, `width`, `height`, `radius`,
`x1` … `y3`, `text`, `size`), each number a `Float32` and `text` a
string, then `color`."

### The compiler

- The typed program gains a fifth shape, `Text`. A draw's arguments are
  held in source order with their types (`args`, in place of the numbers
  and the color), so the emitter evaluates them in the order written.
  This changes `src/tir.rs`, a contract.
- The checker matches `Draw.text(` as it matches the shapes, and gives
  the diagnostics above. The GPU checker gives the text error in place
  of the `String` error and of each draw-placement error.
- The effect analysis keeps its rules: it walks a draw's `args`, and the
  `String` argument keeps the loop on one core. Every other reader of a
  draw (`midnight plan`, `midnight loops`, the overwrite check, the
  emitter and the GPU lowering) walks `args` too.
- The emitter calls `mn_draw_text(x, y, text, size, color)`.
- In a program that draws text, the driver writes `midnight_font.h`, the
  font's table made from `runtime/font.txt`, beside `midnight_window.c`,
  and builds that file with `-DMN_TEXT`; generated code never includes
  `midnight_font.h`. A program that draws no text is built without
  `MN_TEXT`: its generated C and its shaders are byte for byte those of
  0.9.
- `ljust` and `rjust` take an optional second argument, a `String`.
- The evals' harness: the `draws` check's fallback for a line it does
  not read is renamed `Other`, and a `Draw.text` line is compared by its
  text; reading its arguments waits for a task that draws text.

### The runtime

- **The record.** A draw of text is one record of 32 bytes, of kind
  `MN_DRAW_TEXT`, holding `x`, `y` and `size` as 32-bit `Float`s and,
  as 32-bit whole numbers, the offset and length of its string's bytes
  in a byte array that belongs to the list of draws. The bytes are
  copied when the statement runs; the record holds no pointer and the
  list holds no counted buffer. The array is cleared, swapped and freed
  with the records. A frame whose text would not fit in 2^32 - 1 bytes
  stops the program with `midnight: out of memory`, as any allocation
  that fails does.
- `midnight_rt.h`, a contract, gains `MN_DRAW_TEXT`, the text record's
  layout and `mn_draw_text`, which is never called in a piece: "Several
  threads" says so at the function, and a debug build checks it.
  `midnight_window.h` gains the frame's text bytes, which stay valid as
  long as its spans.
- **Rendering.** When a frame is rendered, `u` is computed on the CPU for
  each record of text, and the record is replaced by one record for each
  character that shows a glyph (not a space, U+00A0 or `"\n"`): the
  text's `x` and `y`, `u`, the glyph's index, the cell's first column
  `6 * k` and first row `12 * i`, and the color. The records are made a
  piece at a time, as many as the buffer of records holds, so a long
  text needs no more memory than a frame of shapes. A span counts one
  upload when it has a record after this, so what `MIDNIGHT_GPU=stats`
  counts is what the same frame without its text counts. These records
  are private to `midnight_window.c`.
- **The shader.** Built with `MN_TEXT`, the shape pipeline has the glyphs
  as binding 1, a uniform array written once when the pipeline is made,
  and its shader has the glyph's kind; built without it, the pipeline is
  0.9's. A glyph's quad is its cell's rectangle, made one pixel larger
  and clamped, as for the shapes. The fragment stage finds the column
  and row of the font's pixel that holds the center, among the cell's
  own six columns and twelve rows: it may estimate them with a division,
  clamped to the cell, and then moves to the neighbor, never leaving the
  cell, while a bound's test says so, at most seven steps for a column
  and thirteen for a row; every bound is computed as above, every
  product through the xor barrier. A center left of the cell's first
  bound, or at or right of its last, and the same for rows, is not
  covered by this record; the record of the cell it is in decides it.
  The tests alone decide.
- `midnight_rt.c` keeps the list and never renders; it has no font.

### The reference renderer

`tests/render/mod.rs` reads `runtime/font.txt`, reads the text of a draw
from the `draws` answer, undoing the escapes above, and draws text by
the rule above, apart from the shader. Its unit tests: two characters
side by side and two lines share their bounds; a size that is a multiple
of 12 at scale 1 puts each pixel of the font on one pixel; sizes that
make `u` inexact; the replacement glyph and `ð`; `"\n"` at the start,
twice in a row and at the end; a NaN, a `size` of zero and a negative
`size`.

### What a draw of text costs

- A draw of text in ordinary code appends 32 bytes and the bytes of its
  string to the frame's list.
- When a shown frame is rendered, the CPU writes 32 bytes for each
  character that shows a glyph, and the device tests every pixel of each
  such character's cell, made one pixel larger.
- `bench/draws.sh` gains text, and "What a draw costs" its numbers on
  the RTX 5090, the integrated Radeon and `llvmpipe`: lines of 40
  characters at 24 points, up to 100,000 characters a frame.

### The example

`examples/catch.12am`: a basket moved with the arrow keys catches
falling stars; the score is drawn at the top left, padded with zeros,
and after three missed stars "GAME OVER" is drawn centered, with the
score under it. It draws text and shapes, reads the keyboard, and runs
headless with its `.drive`, `.draws` and `.out`.

### Slices

1. **The language, with no device.** The typed program's `Text` and
   `args`, the checker and its diagnostics, the GPU checker, the emitter,
   `mn_draw_text`, the record and the byte array, `draws` and JSON,
   `ljust` and `rjust`, the harness's fallback, and the tests that need

## Decisions

- **The font is monogram.** It is CC0 by its author's statement on its
  page and in its files, an original design, made for games, with
  lowercase letters and descenders, and its strokes read well at the
  sizes games use. Any program can contain it with no notice.
- **One font, whose characters are all one width.** The size of text is
  then arithmetic on `length`, digits that change do not move, and no
  call to measure is needed.
- **A statement under `Draw`, named `text`.** It is the word most
  toolkits use, and it sits beside the shapes as a noun.
- **Position first, color last.** The shapes' order, so there is one
  order; a string where a number belongs is a type error the compiler
  explains.
- **The top left corner, and `size` the height of a line.** Every
  toolkit with a built-in bitmap font anchors at the top left, and a
  height in points is a length like every other argument of `Draw`. A
  font added later keeps both meanings.
- **`"\n"` starts a line; anything else is one cell.** A newline is the
  commonest thing other toolkits fail to handle; with one rule for the
  rest, the width of a line is its count of characters.
- **A visible replacement glyph.** A character the font lacks is seen
  where it stands, and the text after it stays where the arithmetic puts
  it.
- **Pixels of the font are rectangles under 0009's rule.** Text is then
  exact on every device by the same definition and the same tests as
  the shapes, on one grid for the whole text.
- **Not in GPU systems, and on one core.** Both follow from what strings
  already are, so nothing new is needed for either.
- **The bytes are copied into the frame.** The list holds no counted
  buffer and no pointer, so it stays plain bytes that pieces, the device
  and debug builds already handle.
- **The font's table only where text is drawn.** A program that draws no
  text is built as before, so this spec changes no program it does not
  concern.
- **`ljust` and `rjust` take a padding string.** Scores are padded with
  zeros; Ruby's methods do it with the meaning they have there.

## Measured in planning

From the planning probe on the RTX 5090, RADV and `llvmpipe`, over
10,080 pictures a variant and device: targets of 256 by 256 and 250 by
200 pixels at scales 1, 1.25, 1.5 and 2; a font of 8 by 8 cells, the
same with its rows doubled (8 by 16) and with two blank rows above and
below (8 by 12), and random glyphs in cells of 6 by 7 and 8 by 16;
strings of one line; positions on whole points, halves and anywhere;
sizes multiples of the cell's height and anywhere. Monogram's cell and
text of several lines follow the same rule and are tested by
`window_drawn`.

- The rule, with the barrier and the correction, gave every opaque
  picture byte for byte as the rule computed on the CPU, on all three
  devices, with the font in a storage buffer, a texture or a uniform,
  one instance a glyph or one a line; counters of every covered pixel
  agreed in the translucent pictures too. A binary search over the
  bounds in place of the estimate gave the same pictures.
- Without the barrier, the 5090 and RADV fused `x + c * u` and differed
  from the rule in 7 of 10,080 pictures; `llvmpipe` did not fuse.
- Without the correction, the estimate alone was wrong in 13 opaque
  pictures of 5,040 on the 5090, 14 on `llvmpipe` and 437 on RADV
  (660,591 pixels), never by more than one column or row. RADV's
  division goes wrong exactly where the quotient is a whole number:
  text at whole or half points at a size that is a multiple of the
  cell's height, the commonest case.
- Translucent text kept 0009's allowance: the 5090 equal to the rule,
  RADV within 2 and `llvmpipe` within 3, never more than one per
  translucent draw over a pixel.
- On the CPU: computing a bound with a fused multiply-add instead of a
  product and a sum changed 31 covered pixels of 370 million; a glyph
  placed from its own rounded origin instead of the text's changed 49;
  `floor((px - x) / u)`, correctly rounded, chose the wrong column or
  row at 1,301 pixels and never by more than one. Hence the barrier, the
  bounds from the start of the text, and the correction after the
  estimate.
- With a cell 12 high, `u` is exact for whole sizes that are multiples
  of 3 (66 of the sizes 1 to 200), and the end of a line,
  `x + (6 * n) * u`, is then exactly `x + n * size / 2`; for lines of 1
  to 100 characters at the other whole sizes up to 200 it is in 12,522
  of 13,400 pairs.
- What a frame costs, with the records uploaded each frame, one instance
  a glyph, the font in a storage buffer, cells of 16 by 16 pixels:

  | | RTX 5090 | RADV | `llvmpipe` |
  |---|---|---|---|
  | 10,000 rectangles of 16 by 16 | 0.069 ms | 0.60 ms | 4.1 ms |
  | 10,000 glyphs | 0.075 ms | 1.37 ms | 5.3 ms |
  | 100,000 rectangles of 16 by 16 | 0.33 ms | 5.7 ms | 35.9 ms |
  | 100,000 glyphs | 0.41 ms | 13.4 ms | 43.2 ms |

  A glyph costs about what a rectangle of its cell costs on the 5090,
  2.3 times on RADV and 1.2 to 1.3 times on `llvmpipe`. The font in a
  texture or a uniform cost within 5% of the storage buffer.
- Font pixels are all one width at sizes that are multiples of 24 at
  scales 1, 1.5 and 2, of 48 at 1.25, and of 12 at 1 and 2, for
  positions whole, half and anywhere and windows of 320, 333, 401 and
  1,280 points.

### Differences from the design

- `MIDNIGHT_GPU=stats`: a span of text alone that shows a glyph counts one
  upload, where the same frame without its text has no span to count. The
  counts are equal for spans that also hold a shape, as in `text_stats`;
  `docs/running.md` says how a frame's uploads are counted.
- `-DMN_TEXT` is on the one command line that builds a program, so
  `midnight_rt.c` is compiled with it too and makes no use of it.
- An argument given by name to `Draw.text` is the statement's one error
  about its form, as rule 1 says; the shapes keep going on to the color and
  the count after it, as before.
- The records that hold a glyph are a kind of `midnight_window.c`'s own,
  made 4,096 at a time into a staging array on the CPU.
- The generated C of every program carries the compiler's version, so
  criterion 11 compares it with that string set aside.
